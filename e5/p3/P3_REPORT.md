# P3：参考路径预热实验的验证结果与诊断

结论：在固定 seed=11、2,000 条训练数据、750 次总更新的设置下，P3（前 150 步参考路径 CE，后 600 步联合训练）未改善目标失败模式。统一 BF16 独立验证的答案准确率为 2/200，control_v1 为 6/200；严格步骤匹配为 5/478，基线为 6/478。解释仍集中于少量与题目不匹配的乘法模板。保留 control_v1；将 P3 作为有诊断证据的负结果，不据此启动新的超参数扫描或测试集选型。

## 1. 审计范围与可复现性

读取 `server_backup_p3` 下完整验证导出、P0 原始干预和梯度记录、三个参考路径 probe，以及训练 contract、750 条更新日志和 session。对照 `server_backup_p1` 中 control/P1 与 `server_backup_p2` 中 P2 的原始记录。分析脚本为 `e5/analyze_p3.py`，输出目录为 `e5/p3_analysis/`。

以下核验通过：

- 四个模型的 200 道验证题 ID、题目、参考答案、参考公式与监督槽位一致；答案从原始文本重新提取，解释指标重新计算。
- 四个模型的 P0 训练/验证各 32 题及循环 donor 配对一致；NLL、文本变化、梯度范数和余弦摘要与原始记录相符。
- 三个参考 probe 使用相同 seed-11 验证子集。control/P3 的 probe latent 原文与各自独立验证导出逐题相同。
- P3 contract 的初始化身份、公共配置、数据、样本顺序、训练源文件和资产 manifest 哈希与本地记录相符。
- 日志覆盖连续第 1–750 次更新。1–150 为 `reference_only`，未计算损失为 null；151–750 为 `joint`，四项损失均有限。损失加和与连续学习率计划符合代码。
- P3 最终 checkpoint 身份在独立验证、P0、最终参考 probe 中一致：`54237b3eccad670a6f71f3bc26f01e53957075cb5fcf5de44a20be18a2ce33c0`。

本次未下载或重新哈希模型权重，也未直接检查 checkpoint 内嵌 contract/优化器状态；以上是导出之间及与本地代码的数据核验，不是重新执行 GPU 推理。历史 manifest 不一致和曾受测试结果影响的基线选择仍需披露。

## 2. 统一独立验证：准确率没有收益，模板问题仍在

以下均使用 BF16 权重 + BF16 autocast、固定 4 次 latent 迭代。答案分母为 200；参考步骤分母为 478 个有效监督槽；生成算式分母为全部 1,000 个输出槽（含没有参考监督的 PAD 槽）。

| 指标 | control | P1 | P2 | P3 |
|---|---:|---:|---:|---:|
| 答案正确 | 6/200 | 6/200 | 6/200 | 2/200 |
| 严格步骤匹配 | 6/478 | 6/478 | 3/478 | 5/478 |
| 保守公式等价匹配 | 9/478 | 10/478 | 6/478 | 6/478 |
| 操作数匹配（原 E4 口径） | 10/478 | 11/478 | 7/478 | 7/478 |
| 有序首操作数匹配（事后诊断） | 26/478 | 27/478 | 27/478 | 22/478 |
| 运算符匹配 | 190/478 | 190/478 | 190/478 | 188/478 |
| 中间结果匹配 | 26/478 | 19/478 | 17/478 | 16/478 |
| 生成算式算术成立 | 1000/1000 | 1000/1000 | 1000/1000 | 997/1000 |
| 答案解析失败 / 截断 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| 解释生成截断 | 0 | 0 | 0 | 0 |

有序首操作数指标沿用 P2 事后定义：按合并公式的出现顺序，比较每个有效槽的首数值操作数列表。它不是预先注册的独立终点。保守等价检查也不等于完整数学或语义等价。

相对 control，P3 有 128/200 个数值答案改变；共同答对 1 题，新增答对 1 题、丢失 5 题。新增 ID 为 `gsm8k-aug-train-2069`，丢失 ID 后缀为 2005、2030、2057、2160、2192。严格步骤新增匹配 4 槽、丢失 5 槽。

答案配对的双侧精确 McNemar 检验为 p=0.21875（1 个新增、5 个丢失）。这是事后描述性检验，不足以声称显著退化，更不代表效果相同。当前可以写“观察到准确率下降，未发现改善”，不能写“已证明预热必然有害”。

P3 五个槽的不同输出数为 `[4,4,3,4,3]`。第一个槽中 `3*2=6` 出现 99/200 次，`2*3=6` 出现 70/200 次；第三个槽中 `2*2=4` 出现 126/200 次。算术成立率高而任务步骤匹配低，说明固定模板仍主导输出。

三处算术错误均为 `15+10=30`，分别位于 2053 的 slot=1、2096 的 slot=3、2182 的 slot=1。其中 2053 的该槽为 PAD，无参考监督；仍计入全部生成槽的算术检查，不计入 478 个有效槽的参考匹配指标。

P3 答对的两题也没有对应正确的解码步骤：

- 2004：参考计算为 `200-50*.01*200=100`、`2*100=200`。模型答案为 200，但解码为 `3*2=6`、`2*3=6` 等模板。
- 2069：参考计算为 `150/60=2.5`、`60*2.5=150`。模型答案为 150，但解码同样是 2、3、6 的乘法模板。

这些输出不能证明内部不存在正确计算，但不能作为可解释步骤忠实反映解题过程的证据。

## 3. 参考路径自由生成：没有建立可靠教师的证据

参考路径仅接收题目，不提供 gold CoT 或答案，最多生成 512 个新 token；latent 答案预算为 64 token。以下不是等推理预算或速度比较。

| 模型 | 参考答案正确 | Latent 答案正确 | 参考截断 | 参考解析失败 |
|---|---:|---:|---:|---:|
| control 第 750 步 | 3/32 | 1/32 | 1/32 | 1/32 |
| P3 第 150 步 | 0/32 | 0/32 | 9/32 | 9/32 |
| P3 第 750 步 | 1/32 | 0/32 | 2/32 | 2/32 |

每组的截断和解析失败恰好发生在同一批样本。P3 第 750 步的唯一参考答案匹配来自 2040，也是 control 答对的三题之一；没有新增参考答对题。

逐条查看所有“参考答案正确”的原文后发现：control 的三条、P3 的一条均包含明显算术错误。例如：

| 模型 / ID 后缀 | 生成的公式片段 | 最终答案 |
|---|---|---:|
| control / 2040 | `50*100=50`，反复出现 | 50 |
| control / 2135 | `14*2=14`、`14+2=14` | 14 |
| control / 2157 | `4*2=2`、`2*4=2`、`2*2=2` | 2 |
| P3 / 2040 | `50*100=50`，重复五次 | 50 |

因此这里的“正确”仅指匹配冻结标签，不能升级为正确推理。2040 本身也存在题意与参考解法的疑点：题目提到需要 50 张照片，预算可打印 100 张，参考却做 `100-50=50`。本次保留冻结标签，不事后改分；该样本尤其不适合证明教师可靠性。

另对全部参考输出中完整 `<<...>>` 公式进行事后算术检查：control 为 5/140 成立，P3 第 150 步为 0/719，第 750 步为 2/223。control 的 32/32 条输出、P3 两阶段各 31/32 条输出至少包含一处错误公式。这些分母受重复生成和长度影响，仅描述生成公式，不能当作逐题准确率或完整语义评价；截断的残缺公式未计入。

P3 第 150 步尚未训练 latent/decoder 的联合目标，其 latent 0/32 不能与训练完成模型等价解释。也没有 shared_init 或 control 第 150 步的同协议 probe，不能声称“预热使参考能力从 3/32 降到 0/32”。能确认的是：此次 150 步预热结束时没有形成可用的强参考路径；随后联合训练降低了截断频率，最终表现仍未优于已完成训练的 control。

## 4. P0：答案条件概率出现正向信号，但没有转化为准确解释

P0 使用 FP32 master + BF16 autocast，与独立 BF16 权重评测不同。以下仅在 P0 内横向比较。NLL 差值定义为“交换其他题的 latent 后 − 原始”，正值表示原始 latent 对 gold 的条件概率更有利。

| 验证子集指标 | control | P1 | P2 | P3 |
|---|---:|---:|---:|---:|
| 数值答案改变 | 17/32 | 16/32 | 14/32 | 15/32 |
| 原始 / 交换后答对 | 0 / 0 | 0 / 0 | 1 / 1 | 0 / 0 |
| 平均答案 NLL 差 | -0.04218 | -0.00551 | +0.01055 | +0.05795 |
| 原始 latent 的答案 NLL 更优 | 10/32 | 13/32 | 19/32 | 20/32 |
| 解释 token 序列改变 | 22/71 | 38/71 | 48/71 | 38/71 |
| 改变且通过保守等价检查 | 1/22 | 26/38 | 12/48 | 13/38 |
| 改变但未通过保守等价检查 | 21/71 | 12/71 | 36/71 | 25/71 |
| 平均解释 NLL 差 | -0.002626 | -0.001636 | -0.000455 | +0.002149 |
| 原始 / 交换后严格步骤匹配 | 1 / 0 | 1 / 1 | 0 / 0 | 0 / 0 |

P3 的答案 NLL 差中位数为 +0.02365；训练子集平均差为 +0.07347，23/32 题原始 latent 更优。这个信号应保留，不能概括为 latent 完全无用。但验证子集原始和交换后均 0 题答对，原始解释仍 0/71 严格匹配；交换后性能变化也不证明推理忠实性。

解释 NLL 的正均值较小，验证中只有 33/71 槽原始更优，不能说逐槽稳定改善。训练子集原始答对 0/32、交换后 1/32，也提示条件概率优势不能直接等同于贪心生成准确率优势。

验证集答案 CE 与解释 CE 的梯度余弦：P3 在 shared（reasoner 与 projector 合并）组平均 +0.14427，3/32 为负；reasoner 单独平均 +0.00860，11/32 为负。control 对应 reasoner 平均 -0.00468，17/32 为负。这里是训练终点、eval 模式的小样本观测，不能推出冲突在整个训练中被消除，也不能据此确定失败的因果机制。

## 5. 训练记录与比较限制

完整 session 为 3476.25 秒（57.94 分钟），峰值 allocated 显存 4.724 GiB。这个时间包含循环内验证和保存，但不含模型加载，也不是平台总租用时间。最后一条日志的 3415.26 秒（56.92 分钟）在最终验证/保存前记录，不能作为完整 session 时间。

训练内第 250/500/750 步验证分别为 5/200、3/200、3/200，采用 FP32 master + BF16 autocast；最终独立 BF16 权重评测为 2/200。不要择高报告或混合协议。没有进行同过程的 200 题精度对照复跑，因此精度设置差异是已确认的协议区别，未证明是数值差异的唯一原因。

源码记录的 `grad_norm` 为裁剪前范数，实际使用阈值 1.0 的梯度裁剪。第 151 步的 64.62 与最终的 13.97 不代表更新时使用了未裁剪梯度。

P3 和 control 都是 750 次总更新，但 P3 的 latent/projector/decoder 联合训练仅有 600 步，且跳过了前段较高学习率；参考阶段与联合阶段的 dropout 随机数消耗也不同。因此结果反映的是整个预热方案，不能单独归因于训练顺序或某项梯度变化。少 150 次联合更新、参考自由生成能力弱都是候选解释，未被这一次实验分别验证。

## 6. 后续处理

1. 保留 control_v1；P3 标记为已完成的探索性负结果，不切换基线。
2. 将 P1/P2/P3 放入报告的诊断与消融部分，区分任务准确率、解释匹配、算术成立、latent 敏感性四类证据。
3. 当前无需继续训练或查看测试集来选择方案。若课程需要最终测试，应先冻结方法和比较方案，再单独执行。
4. 服务器上的 `last.pt`、`reference150.pt` 尚未包含在此次下载中；在释放实例或删除目录前完成权重备份。训练环境、初始化和优化器分组等附加元数据也可一并归档。
