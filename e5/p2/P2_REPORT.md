# P2 首操作数加权：验证结果与判断

结论：按与 control/P1 相同的独立 BF16 评测协议，P2 答案正确数持平，解释匹配下降，没有形成明确收益。继续保留 control_v1，不把 P2 升级为基线；当前不建议追加 P2 随机种子或进行测试集选型。

## 证据与核验范围

读取 `server_backup_p2` 的训练日志、contract、session、验证逐题预测和解码、P0 梯度及交换记录；与 `server_backup_p1` 中的 control/P1 原始记录重算比较。验证集 200 题的 ID、题目、答案、参考算式和槽位一致；P0 训练/验证各 32 题及循环 donor 一致。训练源代码哈希、数据哈希、初始化身份、公共配置和样本顺序哈希均通过核验。日志包含连续 1–750 次更新，损失与梯度范数有限，学习率符合原计划，每步解释系数 1、操作数权重 2。

独立评测与 P0 的 P2 checkpoint 哈希一致：
`8764f7f04060a34a319826fd478f17b4e3d6dd40d2ff6358ec23705d96bca599`。
权重未下载，因此没有在本地重新计算权重文件哈希，也未直接核验 checkpoint 内嵌 contract 与下载 contract 的一致性。

训练 session 用时 4064.05 秒（67.73 分钟），峰值 allocated 显存 4.72 GiB。此时间含循环内验证和保存，不含模型加载；不是总租赁时长。第 750 步日志时间 4000.30 秒早于最后保存结束。

## 先纠正 8/200 与 6/200 的混用

训练内第 250/500/750 步验证分别为 6/200、3/200、8/200；独立评测逐题重算为 6/200。

两条代码路径精度不同：`train_p2.validate` 保留 FP32 master 参数、在 BF16 autocast 下生成；`e3/evaluate.py` 明确执行 `model.to(torch.bfloat16)` 后再生成。参数舍入可能改变自回归贪心输出。这是已确认的协议差异，但未进行完整 200 题的同 checkpoint、同进程精度配对复测，不能断言它已经被证明是唯一原因。

此前将 P2 训练内的 8/200 与 control 独立评测的 6/200 相比，只能作为临时观察，不能作为改进证据。以下表格统一使用独立 BF16 参数 + autocast 的评测协议。

## 统一验证结果

| 指标 | control | P1 | P2 |
|---|---:|---:|---:|
| 答案正确 | 6/200 | 6/200 | 6/200 |
| 严格步骤匹配 | 6/478 | 6/478 | 3/478 |
| 限定算式等价匹配 | 9/478 | 10/478 | 6/478 |
| 操作数匹配（既有 E4 口径） | 10/478 | 11/478 | 7/478 |
| 首操作数匹配（新增描述指标） | 26/478 | 27/478 | 27/478 |
| 运算符匹配 | 190/478 | 190/478 | 190/478 |
| 中间结果匹配 | 26/478 | 19/478 | 17/478 |
| 生成算式算术成立 | 1000/1000 | 1000/1000 | 1000/1000 |
| 解释生成截断 | 0 | 0 | 0 |

478 是有效参考槽位数；1000 是所有生成槽位，包含没有参考步骤的 PAD 槽。算术成立不代表对应题目正确。既有操作数指标比较解析后的操作数集合式表示（排序列表，保留重复），并非首操作数。新指标对每个有效槽位提取按算式顺序排列的首个数值操作数，按精确数值比较整个列表；合并尾部缺少任何算式即不匹配。新指标属于事后描述分析，不是预先冻结的独立主终点。

相对 control：68/200 个数值答案改变，4 题共同正确；P2 新答对 2 题、丢失 2 题，净变化为零。新答对 ID 为 2125、2176，丢失为 2030、2057（均带 `gsm8k-aug-train-` 前缀）。严格步骤匹配新增 2 槽、丢失 5 槽。相对 P1 也是新答对 2 题、丢失 2 题。

## 固定模板问题仍在

五个槽的不同输出数量：control/P1 都为 `[5,2,2,2,2]`，P2 为 `[6,3,3,3,3]`。

例如第二个槽（slot=1）的 200 个输出，P2 为 `2*2=4` 95 次、`2*3=6` 83 次、`3*2=6` 22 次。虽然多了一种模板，但对应参考步骤的准确性没有整体提升。所有生成算式都成立，也不能弥补与具体题目脱节的问题。首操作数只增加一个匹配槽，未支持本次加权假设达成目标。

## 同样本 P0：有答案 NLL 信号，没有解释质量收益

以下为验证子集 32 题、71 个有效解释槽。NLL 差值定义为“交换 − 原始”，正值表示原始 latent 对 gold NLL 更有利。

| 指标 | control | P1 | P2 |
|---|---:|---:|---:|
| 交换后数值答案改变 | 17/32 | 16/32 | 14/32 |
| 原始 / 交换答案正确 | 0 / 0 | 0 / 0 | 1 / 1 |
| 平均答案 NLL 差值 | -0.04218 | -0.00551 | +0.01055 |
| 原始 latent 答案 NLL 更优题数 | 10/32 | 13/32 | 19/32 |
| 解释文本改变 | 22/71 | 38/71 | 48/71 |
| 改变但通过限定等价检查 | 1/22 | 26/38 | 12/48 |
| 改变且未通过限定等价检查 | 21/71 | 12/71 | 36/71 |
| 平均解释 NLL 差值 | -0.002626 | -0.001636 | -0.000455 |
| 原始 / 交换解释严格匹配 | 1 / 0 | 1 / 1 | 0 / 0 |

P2 训练子集平均答案 NLL 差值也为正（+0.02983），验证差值中位数为 +0.01910。这是原始 latent 可能更有用的有限信号，应保留，而不应写成完全无影响。但验证原始/交换各正确 1 题，且原始解释零严格匹配，不能据此声称推理忠实性或实际解题质量提升。跨题交换本身也是分布外干预。

P0 梯度使用三个模型共同的普通解释 CE，**不是 P2 的加权训练目标**。验证共享参数答案/解释平均余弦 P2 为 +0.1150，4/32 为负；reasoner 单独的平均余弦为 -0.00562，17/32 为负。共享集合含 projector，不能拿共享均值替代各模块结论。负余弦接近零且来自训练终点的小样本，不能直接推出梯度冲突造成退化。相关余弦及梯度范数已从逐题记录重算核对。

## 下一步

1. 本轮 P2 可结束：保留为“首操作数权重 2 的单种子实验未改善目标失败模式”的负结果。保留 control_v1；不追加权重扫描，也不进入测试集选型。
2. P1、P2 均无明确解释收益。若继续 P3，先在相同验证子集自由生成参考路径 CoT/答案，与 latent 路径比较，确认参考路径本身是否明显更强。已有参考 CE 来自 teacher forcing，低 CE 不等于能自由生成正确推理。
3. 若该诊断支持教师质量/早期训练顺序假设，再按原计划独立做前 150 步参考路径训练、后 600 步联合训练；这仍是待验证假设，不保证优于现有方法。当前尚未实现或运行 P3。
4. 精度配对复测可以定位 8/200 与 6/200，但不改变当前统一 BF16 协议下 P2 没有收益的事实。如后续改用 FP32 参数评测，应对所有对照一致处理，不能只选 P2 较高的数字。

限制：单种子、小样本验证选择；历史基线选型曾参考测试集；历史 manifest 哈希差异继续披露。此轮未读取测试集数据、未重训、未修改冻结基线。
